# 地理探究问题的实验化

## 为什么需要这一步

学生的问题通常是**现象式**的（「为什么这里水土流失严重」），而工具需要的是**变量式**的（「坡度从 8% 变到 16%，其他不变，流失量怎么变」）。中间这一步——把问题拆成变量、把变量变成对照——正是虚拟实验最容易缺失、也最有教学价值的一环。不要跳过它直接算数。

## 三步流程

### 第一步：判断问题类型

| 学生问的 | 实际上是 | 对应模式 |
|---|---|---|
| 「大概多少」「严不严重」 | 单点估算 | `run` |
| 「会怎样变」「为什么越……越……」 | 单因子关系 | `sweep` |
| 「哪个方案更好」「能减少多少」 | 方案比较 | `compare` |
| 「最主要的原因是什么」 | 因子重要性 | `analyze` |
| 「A 和 B 有什么联系」 | 跨过程关联 | 概念串联，**不做数值合并** |

**判断不了就问一句**，不要猜。宁可多问一句，也不要算一个学生没问的东西。

### 第二步：写出变量方案

在调用工具前，先在回答里明确列出这三行：

```
自变量：植被覆盖度（0% → 100%）
因变量：年土壤流失量 A（t/(ha·a)）
控制变量：坡度 8%、坡长 30 m、降雨侵蚀力 4500、土壤可蚀性 0.030、措施为无
```

这一步是硬要求。学生看到这三行，才知道"对照实验"到底是什么意思。缺了控制变量，结论没有意义。

### 第三步：选工具、选模式、执行

- 坡面土壤流失 → `geolab-soil-erosion` 技能
- 河道弯道冲淤 → `geolab-river-bend` 技能
- 两者都涉及 → 分别执行，**只做概念串联**

## 结论的表述规范

一个合格的结论必须包含四段，缺一不可：

1. **数值**：「覆盖度从 0% 提高到 60%，年流失量由 139.3 降到 12.6 t/(ha·a)。」
2. **关系**：「两者不是线性关系，而是指数衰减——覆盖度越高，继续提高的边际收益越小/越大。」
3. **机理**：为什么会有这个关系（植被截留雨滴、根系固土、增加入渗、减缓流速）。
4. **边界**：「这是多年平均的示例估算，参数取默认值时结论只代表量级趋势；真实坡面需用当地实测参数替换。」

只给数值不给边界，是这类教学工具最常见的误导方式。

## 学生常见误解，遇到就纠正

| 误解 | 纠正方式 |
|---|---|
| 「覆盖度翻倍，流失量就减半」 | 关系是指数衰减而非线性；让学生用 `sweep` 自己看出来 |
| 「坡度越陡流失越多，所以陡坡一定不能种东西」 | 坡度只是 LS 一项，措施与覆盖可以大幅抵消；用 `compare` 做对照 |
| 「凸岸流速慢所以会一直淤」 | 淤积取决于输沙能力下降，还要看上游来沙；模型只给倾向 |
| 「模型算出来是 12.6，明年就是 12.6」 | 多年平均值不等于任一年的实际值，单次暴雨会显著偏离 |
| 「AI 算的所以一定对」 | AI 只负责选参数和解释；**数值是工具算的**，工具本身有明确假设与适用范围 |

## 跨模块问题的处理

当学生问「坡面的泥沙和河流的沉积有什么关系」这类跨越两个尺度的问题时：

✅ 正确处理：分别说明两个尺度各自回答什么，再用「供给—搬运—沉积」的因果链串起来。

❌ 错误处理：把坡面的 `t/(ha·a)` 与河道的 `Pa` 拼成一句话，或者把坡面流失量当作进入河道的泥沙量。

必须说清的一句：
> 这两个模型的口径不同，一个是坡面产沙的估算，一个是河道冲淤倾向的定性判断，它们之间的定量衔接需要泥沙输移比等额外参数，本课程范围不做。

## 参数缺失时怎么办

- 学生没给参数 → 用工具默认值，并在回答里明说「以下按默认参数计算」。
- 学生给的参数超出物理可能范围 → 先指出为什么不合理（覆盖度不可能 130%），再给合理值重算。
- 学生问题本身有歧义 → 给出两种可能的解读，让学生选，不要替学生决定。
